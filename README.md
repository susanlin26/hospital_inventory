# 醫院耗材智慧分析｜Netlify 單平台預覽版 v0.12.0

網站、分析程式、背景匯入與PostgreSQL資料庫均以Netlify為部署目標，不需要Render。這是**待線上驗收的預覽版**，尚未在您的Netlify帳號建立資源或部署，不可宣稱已保證正式環境功能與速度完全不變。

## 執行方式

- 網頁由Netlify提供。
- Netlify Functions執行Node.js入口，再於同一個函式執行環境內啟動隨附的Linux x86_64 Python元件；不連到其他分析主機。這是自行封裝的執行方式，並非Netlify提供Python專用執行環境，仍需實際平台驗證相容性。
- 原有Python算式、Excel解析與產出、權限及改善流程保留。金額仍使用Decimal，沒有改用JavaScript浮點數重算。
- 使用`@netlify/database`取得當次部署對應的Netlify Database連線；資料庫密碼不進網頁。正式連線預設驗證TLS憑證。
- 匯入工作與狀態保存於資料庫，由Netlify背景函式處理，採資料庫鎖避免重複處理；時間接近上限時接續處理。正式部署另有每5分鐘排程喚醒，預覽以操作／輪詢及接續請求喚醒。
- 原有15 MB單檔匯入上限保留；較大檔案分為1 MB片段傳送。超過3 MB的回傳檔案亦分段下載，暫存綁定使用者及登入狀態，逾時清除。暫存下載沿用PostgreSQL儲存與函式資源限制，仍須以實際大型匯出驗收。
- 分析與背景函式設定2 GB記憶體，以對應原Render設定的運算資源；執行區域為Singapore。資料庫請設為相同區域。這些設定會影響Netlify用量費用。

## 已驗證

- 63項Python自動測試通過，涵蓋既有功能、運算與流程回歸，以及新增的分段傳輸完整性、上傳歸屬、檔案下載登入綁定及內部入口保護。
- 3項Node入口測試通過，包含背景工作票證驗證、公開入口不得轉送私有操作，以及隨附執行元件雜湊核對。
- 17項本機HTTPS真實瀏覽器情境通過：登入、實際月報匯入、Excel輸出、改善原因及進度、門檻分段、醫院多選及新增醫院等。另實際完成超過5 MB的有效Excel分段上傳、背景匯入及分段下載，SHA-256核對完全相同。
- 已使用Netlify官方函式封裝工具檢查入口、背景、排程的封裝設定。這不等於已在Netlify執行成功。
- 手機只做390像素寬度模擬，尚未用實體手機驗證。

## 本機速度與結果比對

使用同一個隔離PostgreSQL資料庫、相同月報及相同查詢，舊版採本機HTTPS簽章代理，新版採本機HTTPS函式介面；每種查詢暖機後各測12次，以下為中位數：

| 查詢 | 原v0.11.2 | 新執行介面 | 回傳結果 |
|---|---:|---:|---|
| 耗用品項 | 44.41 ms | 34.12 ms | JSON完全一致 |
| 存貨品項 | 48.20 ms | 31.54 ms | JSON完全一致 |
| 管理總覽 | 89.86 ms | 62.76 ms | JSON完全一致 |
| 跨院比較 | 74.73 ms | 64.68 ms | JSON完全一致 |

本機新程序的首次健康檢查約1.77秒（執行元件已解壓；不含平台排程與全新環境解壓時間）。**以上不是Netlify速度保證**：尚未量測實際冷啟動、資料庫休眠、台灣連線延遲、大量歷史資料及多人同時使用。資料庫與函式休眠／新容器啟動都可能增加等待。沒有達成線上驗收前，不取代現有正式版本。

## 線上驗收尚待完成

1. Netlify Linux x86_64函式實際啟動隨附Python元件，以及資料庫TLS連線、SQL與鎖功能相容性。
2. 所有實際使用流程、15 MB邊界檔案、大型匯出、背景工作中斷及多人同時操作。
3. 新舊版相同資料下的首次開啟、暖機查詢、月報匯入與Excel匯出時間；若較慢，先調整再評估是否採用。
4. 資料庫備份、還原及預覽資料隔離。預覽資料庫可能由正式分支複製，不能假設預覽天然沒有真實資料。
